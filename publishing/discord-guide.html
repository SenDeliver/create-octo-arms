Roles Octo Arms and Landing Legs are ping roles only, no permissions. Members pick them in Onboarding or later in Channels & Roles.

Daily check (a few minutes)

  1. #help: open posts without solved. Reply or ask for the log.
  2. #moderator-only: any Discord notice.
  3. Mod channels: questions that belong in #help? Reply "please open a #help post with your log".
  4. Mod queue: the inbox icon (top right) shows reports and mentions.
Reply fast in the first weeks. A small server lives on the owner answering.

Release a version

flowchart LR A[Release on Modrinth / CurseForge] --> B[Post in #announcements] B --> C[Ping the mod role] C --> D[Click Publish] D --> E[Short note in the mod channel] E --> F[Clip in #dev-log or mod channel]

Post template

## Octo Arms 1.3.2 is out
@Octo Arms
- What changed, one line each
- Fixes: ...
Client only / Client + server: update both
Needs: Create 6.0.x, NeoForge 21.1
Download: <modrinth link> · <curseforge link>
  • Type @Octo Arms and pick the role from the list. As owner you can always ping it.
  • Publish button under the message: sends it to servers that follow the channel. Do it once, after the text is final.
  • Say if the server needs updating too (patch = client only, minor = client + server).
  • Wrap links in <> to hide the big preview: <https://...>.
  • Optional: GitHub releases webhook (see the setup kit) can post automatically, but it cannot ping roles. Then add a short ping message.

Dev log

  • Post WIP clips, gifs, plans, beta jars. Members reply in a thread under each post.
  • One post per topic. Title-style first line: **Landing Legs: terrain snapping**.
  • Beta jars: say clearly "beta, back up your world".
  • Ask questions here ("which feature next?"). Use a Poll (the + button in the composer).

Help forum

  1. Check the post has the mod tag. Wrong tag: open the post menu, Edit Tags.
  2. Ask for: mod version, Create version, NeoForge version, latest.log or crash report (on mclo.gs), client or server.
  3. Fixed: add tag solved, then post menu, Close Post.
  4. Real bug: link the GitHub issue in the post, add tag bug.
  5. Same question many times? Add it to that mod's pinned FAQ (right-click, Edit Message).

Tags: octo-arms, landing-legs, client, server, crash, bug, config, solved. Max 20 tags per forum.

Add a new mod

flowchart LR A[Category + channel] --> B[Role] B --> C[#help tag] C --> D[Onboarding answer] D --> E[Edit texts] E --> F[Announce]
  • Category + channel: create category named after the mod, then text channel #mod-name inside. Set topic. Post and pin a short FAQ (copy the Landing Legs one as a base).
  • Role: Server Settings, Roles, Create Role. Mod name, a new color, no permissions.
  • #help tag: forum settings, Tags, add mod-name, drag it next to the other mod tags. Edit the guidelines line "Pick the mod tag (...)".
  • Onboarding: Server Settings, Onboarding, Questions. Add an answer to "Which mods do you use?": mod name, one-line description, the channel and the role. If the new channel is not a default channel, it shows only to people who pick it.
  • Texts: edit the pinned "Our mods" message in #rules, the welcome post in #announcements, and the server description (Server Settings, Server Profile).
  • Webhook in the new repo, if you use it.
  • Announce in #announcements with @everyone once, and Publish.
Edit old messages, don't delete and repost: pins and links keep working.

Don'ts

  • Don't share the webhook URL: anyone with it can post as the server. Repos are public.
  • Don't give the mod roles permissions. They are for pings.
  • Don't make a new invite for every place: use the one permanent link.
  • Don't ping @everyone for normal releases, only the mod role.
  • Don't do many edits fast in a row: Discord rate-limits the account (error 429, "Messages Failed To Load"). It clears in about an hour.
