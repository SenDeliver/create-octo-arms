Modrinth steps

  1. Make GitHub repo public (images in the description are raw.githubusercontent links).
  2. modrinth.com → sign in with GitHub → Create project → type Mod.
  3. Fill the shared metadata table. Description = paste publishing/modrinth-description.md.
  4. Upload icon + gallery images.
  5. Versions → Create version: jar, number 1.1.0, Release, NeoForge, 1.21.1, dependencies from the table, changelog from release notes.
  6. Submit for review. First review takes 1 to 3 days. Project URL becomes modrinth.com/mod/octo-arms.
  7. Settings → create a PAT with "Create versions" scope → GitHub repo secret MODRINTH_TOKEN.

CurseForge steps

  1. curseforge.com → Authors → Start a project → Minecraft → Mods.
  2. Name, slug octo-arms, summary, categories, license MIT, icon icon-400.png.
  3. Description: switch editor to Source/HTML and paste publishing/curseforge-description.html.
  4. Upload file: jar, display name Octo Arms 1.1.0, Release, 1.21.1 + NeoForge + Java 21, relations Create required, Sable/JEI optional.
  5. Submit. Note the numeric Project ID from the project page sidebar.
  6. API tokens page → create token → GitHub secrets CURSEFORGE_TOKEN and CURSEFORGE_PROJECT_ID.

After listing: releases are automatic

.github/workflows/publish.yml runs on every GitHub Release: builds the jar, uploads to Modrinth + CurseForge and attaches it to the GitHub release. Changelog: publishing/release-notes-<version>.md if it exists, else the latest ## [x.y.z] section of CHANGELOG.md. For 1.1.0 that picks the full first-release notes, not the short 1.1.0 changelog section.

git tag v1.1.0 && git push origin main v1.1.0
gh release create v1.1.0 --title "Octo Arms 1.1.0" --notes-file publishing/release-notes-1.1.0.md

For 1.1.0 you can either upload by hand on both sites (steps above) or create the GitHub Release after the projects exist and the secrets are set, and let the workflow upload. .github/workflows/build.yml builds every pull request and push to main.
