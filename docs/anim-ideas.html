Tentacle animation: smoothness, clipping, cheap fixes

Octo Arms 1.20.1 branch, 2026-10-25. Code audit of TentacleRenderer, RigVisuals, TentacleGait, TentacleLayer, RigClient, RigServer plus research on procedural limb animation. All fixes client-only, network registrar stays "8", no save-format change.
Already good: Step arcs use partialTick + smoothstep (zero speed at lift and plant), Grip points stay fixed in world space, gait and visual update in the same tick. Geometry is ~90 quads/arm, rebuilt per frame; that is fine and not worth caching (pose changes every frame). Per-frame budget of every idea below is ~200 flops per arm with zero world lookups per frame (collision/light cached per tick).

2. Cheap perf wins (not animation, but free)

  • Style.of builds 5 ResourceLocations by string concat on every drawRig (L53-57, L172) + 6 atlas lookups per arm (L226-227). Make Style static per tier, cache sprites, refresh on resource reload.
  • ~30 Vector3f allocations per arm per frame. Reuse scratch vectors in the renderer (single-threaded).
  • 20 getLightColor per Rig per frame → sample per tick, lerp (M5).
  • Flywheel instancing: not worth it, 4 arms whose transforms change every frame.

3. Techniques worth adopting (from research)

Advance state once per tick, render read-only

Render layers can run >1× per frame (Iris/Oculus shadow pass, inventory paperdoll). Springs integrated inside render() step twice. Keep all springs/damping in ClientTick END (as RigVisuals already does for phase), render only lerps with pt.

Never spring a discrete Grip jump

Grip changes are events; smoothing them makes the pad slide without an arc. Replay the Step (A, B, normals, startTick) with the same curve on every client. Springs only for continuous values: free arm, telescope length, body lag.

Bézier arc with normal-aware lift

m = (A+B)/2
n = normalize(nA+nB); if |nA+nB|<1e-3: n = normalize(body - m)
C = lerp(m, body, 0.5) + n*h       // h ≈ 0.6 (peak is h/2)
P(s) = (1-s)²A + 2s(1-s)C + s²B,  s = smoothstep(t)
Fixes H1 + M2 in one formula, ~15 flops.

Stable elbow pole

dir  = normalize(grip - shoulder)
pole = normalize(faceN*0.6 + bodyUp*0.4)
perp = pole - dir*dot(pole,dir)
if |perp|<1e-3: perp = lastPerp[slot]
perp = lerp(lastPerp, normalize(perp), 0.3); lastPerp = perp
elbow = shoulder + L1*(cos α·dir + sin α·perp)
Keep lastPerp per slot; slerp when the face changes. Fixes M1 whip.

Frame-rate independent damper

dt = Minecraft.getDeltaFrameTime()/20   // seconds
x = lerp(x, goal, 1 - exp(-0.693*dt/halflife))
Use for body-yaw follow (H4), shoulder lag, free arm. Stable at any dt.

Critically damped spring (exact)

y = (4·ln2/halflife)/2; j0 = x-g; j1 = v + j0*y
e = 1/(1 + y·dt + 0.48(y·dt)² + 0.235(y·dt)³)
x = e*(j0 + j1*dt) + g;  v = e*(v - j1*y*dt)
Same as Unity SmoothDamp. For the free hanging arm (M3) with a little under-damping for swing.

Pneumatic settle on plant

Put overshoot on telescope length or elbow angle, not pad position: L1 *= 1 + a·e^(-kτ)·sin(ωτ) over 4-6 ticks after plant. Pad may bump only outward along the face normal, so it never enters the block.

Light like a leash

Vanilla MobRenderer.renderLeash samples block + sky at both ends and lerps each channel per segment. Sample pad light at pad + n*0.5 (outside the face, a solid block reads 0). Shoulder light = the layer's packedLight, free.

Step gating (reference)

TheCymaera minecraft-spider: trigger radius 0.25 standing / 0.8 moving, comfort 1.2, lift 0.35, diagonal-pair cooldown 1 tick; lifted foot inherits body velocity so it never slides; forced step when stretch > comfort. Our gait already does most of this; the IDLE_GAIN re-step from body yaw (H4) is the main leak.

  F --> G[L1-L6 + perf wins]

Each step is verifiable with the existing harness (screenshots in tools/shots/) plus a new scene: 1-wide shaft climb, 2-high tunnel floor→ceiling, outer-corner step, camera spin while Held, Stow while Held, remote watcher under simulated packet loss.

Compatibility: all client-only. M4 changes which Grip points the client picks but the server accepts them (older servers too). H4 is a mixin on LivingEntity body yaw: only while Carried, visual only, no gameplay effect, but it is the one change other mods could notice. Fixes land on 1.21.1 first, cherry-pick to 1.20.1; the files touched are the same on both lines.
