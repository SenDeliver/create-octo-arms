Phase 2 — Air, Crawl, Setting Down, mid-air catch (2026-10-08)

regression: tools/run_all.sh <tag>final run: tools/logs/p2final-*numbers: tools/p2_metrics.py (prints RESULT PASS/FAIL)

Air (design §5)

  • RigAir: worn Rig stack, Air via Create BacktankUtil, use class from the mirrored motion (climb = y > 0, move = any other motion incl. Setting Down, idle = none).
  • Drain on the server only, in the player tick, while Active or Setting Down and Held: per-wearer double accumulator, whole units through BacktankUtil.consumeAir (Create's low and depleted titles come with it).
  • Cost per tick = tier factor × thrift(rig) / ticks-per-Air. thrift returns 1.0: the hook for the enchantment phase.
  • Activating needs Air > 0, on the floor and mid-air. Same rule in creative (Create drains diving Air in creative too).
  • Diving helmet keeps drawing the same Rig Air.

Crawl and Setting Down

  • New RigState.CRAWL (wire ordinal 4, registrar "2"). Active or Setting Down with 0 Air → Crawl, on client and server; Crawl never goes back to Active.
  • Crawl: automatic straight-down descent at crawl.speed, Held-clamped, inputs zeroed, float fix on, no drain. Floor → Stowed. No floor in Reach → holds at the lowest Held point.
  • Setting Down: Held descent; floor → Stowed on feet; blocked before a floor → lets go (Stowed), vanilla fall from there. The spike's "back to Active" is gone.
  • Mid-air Double Jump with Air: Falling until a Grip is in Reach, then Active, fall reset. The fall step is swept (Grips.firstHeld) so a fast fall cannot step over a thin Held band. Falling with 0 Air never grabs again.

Server checks

  • Order: worn/alive, finite, Air, Held. New wearer claiming a carry with 0 Air → told Stowed. Carrying with 0 Air → Crawl (wearer told).
  • Crawl mirror: x = z = 0, y in [−1.05·crawl, 0]. Claim or server-seen move up / sideways faster than crawl → count; > 10 → forced Falling, sticky until Stowed (warn "moves against Crawl").
  • Crawl dropped only by the 10-tick silence timeout resumes on the next Crawl claim (a client hitch no longer drops the wearer).
  • Vanilla float counter (aboveGroundTickCount) reset whenever the Rig carries (accessor mixin): a still wearer sends no move packets, so a catch after a long fall used to be kicked.
  • Kept: sticky Held reject, Held check in every carrying state, finite checks, silence timeout.

Phase 3 — Rig Settings, key-only mode, Server Config, tooltips; phase-2 fix-ups (2026-10-09)

Rig Settings

  • Component tentaworks:rig_settings on each Rig item: standing_height (0 … Reach, default 1.5), speed (min(4.3, speed.max) … speed.max, default 5.6), activation (double_jump / key). All fields optional: old Rigs = defaults.
  • Clamped on write (server, RigSettingsPacket) and on every read (client and server), so a lower config later still wins. Rounded to 0.1.
  • Kept through drop/pick up, relog and Rig Block place/pick up (Create's Components patch).

Screen and keys

  • RigSettingsScreen (AbstractSimiScreen): Create's wand panel stretched to 3 rows, ScrollInputs (Shift = steps of 0.5), SelectionScrollInput for the mode, Create scroll sound, confirm button, big Rig on the side. Footer: Reach and top Speed from the server; in key-only mode the toggle key or a "bind it" hint.
  • Open: sneak + use in the air with a Rig in either hand (no equip). Sneak + use on a block still places the Rig Block. Or the Rig Settings key while worn.
  • Keys (category Octo Arms), both unbound by default (design §7): key.tentaworks.settings, key.tentaworks.toggle.
  • Close → packet with the slot (main hand, off hand, chest) → server clamps and writes the component.

Movement uses the settings

  • Standing Height: on activation from a floor the Rig moves the feet to floor + Standing Height (up or down); Idle then holds; Space/Shift move freely up to the Reach. The lift ends at the target, on any height key, or when Held stops it.
  • Speed: Active and Setting Down step = Speed / 20; the server still clamps the mirrored motion to speed.max. Sprint key ignored.
  • Key-only: the toggle key does what a Double Jump did (activate incl. mid-air catch, Set Down, let go in Crawl); Double Jump stays vanilla (two plain jumps; while Active, Space is just "up").

Phase-2 fix-ups

  • Double Jump (or toggle key) in Crawl lets go: Stowed, vanilla fall damage.
  • Crawl losing Grips → Falling → re-grabs into Crawl at 0 Air (swept catch), into Active with Air. Server resets its Crawl-violation count on a legit re-grab. If the server forced Falling (moving against Crawl), the client does not re-grab until Stowed.
  • Creative (server game mode, never a client claim): no drain, activation at 0 Air, never Crawl.
  • Long fall: vanilla's float check zeroes the Y move (if (d7 > -0.5 || d7 < 0.5) d7 = 0 is always true), so any 80 ticks in the air kick — confirmed by a negative control. RigServer.fallGuard resets the counter for Rig wearers whose server Y drops more than 0.1 per tick; a hovering client gains nothing.

Decisions taken (docs did not say)

  • Standing Height = target height on activation from a floor (both directions); Idle then holds the spot, Space/Shift change it freely (design §3). No "spring back" to Standing Height: it would break hanging/climbing.
  • Sprint key ignored while Active: the Speed setting is the one speed (walk … speed.max, default sprint 5.6).
  • Sneak + use in the air opens the screen; sneak + use on a block places the Rig Block (phase-1 behaviour kept).
  • Both keys unbound by default (design §7 for the settings key; the toggle key the same). The screen shows a hint when Key only is chosen without a bound key.
  • Key-only toggle mirrors Double Jump everywhere (mid-air catch, Set Down, let go in Crawl); in Falling and Setting Down it does nothing, as Double Jump.
  • Fall guard applies to every Rig wearer (also Stowed), only while the server sees them really falling (> 0.1 block per tick); non-wearers keep vanilla behaviour.
  • Creative switched on mid-Crawl turns Crawl back into Active.

Three enchantments (data-driven)

Effects (RigEnchants, client and server)

  • Level from the stack's own holder via EnchantmentHelper.getItemEnchantmentLevel, clamped to the max level.
  • Far Reach: TentacleRigItem.reach(stack) = tier + level × farReachPerLevel (cap 16): Held check both sides, Grip search, Standing Height clamp, screen.

  • Swift: client step and server clamp × (1 + level × swiftPerLevel); TentacleRigItem.topSpeed. The stored Speed setting stays within walk … speed.max.

Gait (rig/TentacleGait, client)

  • Four body-relative slots: 0 front-left, 1 front-right, 2 back-left, 3 back-right (= upper-left, upper-right, lower-left, lower-right shoulder). Each aims at a spread target out on its own body diagonal (0.5 × Reach, front slots raised, back slots lowered 0.35 × Reach), so floors, walls and ceilings all get four spread Grips.
  • Candidates: every exposed full-block face that looks at the body; a point is pulled into reach. Score = distance² to the target + a separation penalty (8 × (1.7 − gap)²) against the other Grips.
  • A planted Tentacle keeps its Grip until it is invalid or out of keep distance (forced Step), falls behind its target by 0.35 × Reach along the move (Step ahead by the same stride), or, Idle, a clearly better point exists (squared score gain ≥ 0.5).
  • At most two steppers, always a diagonal pair (0+3, 1+2, alternating); a voluntary Step never leaves fewer than two planted. A slot never lifts on the tick it planted.
  • Step time = clamp(round(1 / blocks per tick), 2, 7) ticks: 4 ticks at 5.6 b/s, 2 at 10.4, 7 when Idle. The arc (lift 0.3 + 0.3 × distance, max 1) is drawn only: the slot already carries its new Grip.
  • Reach margins: picks ≤ Reach + overshoot (overshoot = clamp(0.68 − top speed per tick, 0, 0.3) = 0.26 by default) from the body after the move and at plant time; keep ≤ Reach + 0.68 from the body before and after the move (the server checks the packet against its pre-move position and its tick against the post-move one, allowing Reach + 0.75). The post-move body uses the collided move.
  • On activation / after Falling (no Grip at all) all four Grips are taken at once; the arms unfold visually.

Decisions taken
